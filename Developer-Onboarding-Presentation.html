Section 2

CI/CD Bots & Automated Checks

Every repository needs 4 automated checks on pull requests. These catch bugs, enforce code quality, verify deployments, and provide AI review — without manual effort.

The 4 Essential Checks
  • Sentry Bot — Catches unhandled errors tied to your PR changes
  • Vercel Bot — Auto-deploys preview URLs for every PR
  • GitHub Actions — Runs lints, formatting, and tests
  • Claude Bot — AI-powered code review via @claude mentions

1. Sentry Bot Setup

What It Does

Sentry monitors runtime errors and performance issues. The GitHub integration:

  • Comments on PRs when changes touch error-prone functions
  • Links stack traces to exact file/line in your repo
  • Tracks releases per deploy
  • Auto-assigns alerts via CODEOWNERS

Installation Steps

  1. Create Sentry project at sentry.io → Select platform (Django/Next.js)
  2. Install GitHub App:
    • In Sentry: Settings → Integrations → GitHub → Install
    • Click "Add Installation" → Select repositories
    • Or install directly: github.com/apps/sentry
  3. Install SDK in project:

Django (backend):

pip install sentry-sdk
# Add to settings.py:
import sentry_sdk
sentry_sdk.init(
    dsn=os.environ.get("SENTRY_DSN"),
    traces_sample_rate=1.0,
)

Next.js (frontend):

npx @sentry/wizard@latest -i nextjs
  1. Set environment variable: 
    # .env
SENTRY_DSN=https://your-key@o123.ingest.sentry.io/456
Verification
  • Sentry project exists at sentry.io
  • GitHub integration shows "Installed"
  • SDK installed and SENTRY_DSN in .env
  • Test error appears in dashboard

2. Vercel Bot Setup

What It Does

Vercel auto-deploys your Next.js frontend on every PR and push:

  • Creates preview deployment URL for each PR
  • Comments on PRs with preview link + deploy status
  • Auto-deploys to production on merges to main
  • Shows build errors directly in PR checks

Installation Steps

  1. Install GitHub App:
    • Go to github.com/apps/vercel → Install
    • Select organization and repositories
  2. Link project on Vercel:
    • Go to vercel.com/new → Import GitHub repository
    • Configure build settings:
      • Framework: Next.js (auto-detected)
      • Root Directory: Set if frontend is in subdirectory
      • Build Command: npm run build
      • Output Directory: .next
    • Click Deploy
  3. Configure environment variables:
    • Vercel Dashboard → Your Project → Settings → Environment Variables
    • Add all required env vars (NEXT_PUBLIC_API_URL, SENTRY_DSN, etc.)
    • Set for: Production, Preview, Development
Verification
  • Vercel GitHub app installed on org
  • Project imported and first deploy successful
  • Environment variables set for all environments
  • Test PR triggers preview deployment comment

3. GitHub Actions (Lints, Formats, Tests)

What It Does

GitHub Actions runs code quality checks automatically on every push and PR. Enforces standards before code can be merged.

Backend Workflow (Django + Python)

Create .github/workflows/backend.yml:

name: Backend CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  lint-format-test:
    runs-on: ubuntu-latest

    services:
      postgres:
        image: postgres:16
        env:
          POSTGRES_USER: postgres
          POSTGRES_PASSWORD: postgres
          POSTGRES_DB: test_db
        ports:
          - 5432:5432
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5

    steps:
      - uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.12"

      - name: Install uv
        run: pip install uv

      - name: Install dependencies
        run: uv pip install -r requirements.txt --system

      - name: Lint with ruff
        run: ruff check .

      - name: Format check with ruff
        run: ruff format --check .

      - name: Type check with mypy
        run: mypy . --ignore-missing-imports

      - name: Run tests with pytest
        env:
          DATABASE_URL: postgres://postgres:postgres@localhost:5432/test_db
          DJANGO_SETTINGS_MODULE: config.settings.test
        run: pytest --tb=short -q

Frontend Workflow (Next.js + TypeScript)

Create .github/workflows/frontend.yml:

name: Frontend CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  lint-format-test:
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4

      - name: Set up Node.js
        uses: actions/setup-node@v4
        with:
          node-version: "20"
          cache: "npm"
          cache-dependency-path: frontend/package-lock.json

      - name: Install dependencies
        working-directory: frontend
        run: npm ci

      - name: Lint
        working-directory: frontend
        run: npm run lint

      - name: Type check
        working-directory: frontend
        run: npx tsc --noEmit

      - name: Format check
        working-directory: frontend
        run: npx prettier --check .

      - name: Run tests
        working-directory: frontend
        run: npm test -- --passWithNoTests
Important

Adjust working-directory if your frontend is at the repo root instead of a subdirectory.

Verification
  • .github/workflows/backend.yml exists
  • .github/workflows/frontend.yml exists
  • Push to branch triggers workflows
  • PR shows green/red check status

4. Claude Bot (AI-Powered Review)

What It Does

Claude reviews your PRs with AI-powered analysis. When someone comments @claude:

  • Reads entire PR diff and linked issues
  • Provides hyper-critical code review with actionable feedback
  • Can implement changes by pushing commits
  • Reviews against acceptance criteria from tickets

Installation Steps

Part 1: Install Claude GitHub App

Inside Claude Code terminal, run:

/install-github-app

Or install manually at github.com/apps/claude → Install → Select repos

Note: You need Owner permissions on the GitHub org.

Part 2: Add GitHub Action Workflow

  1. Add Anthropic API key as repository secret:
    • Repo → Settings → Secrets and variables → Actions
    • Click "New repository secret"
    • Name: ANTHROPIC_API_KEY
    • Value: Your API key (starts with sk-ant-)
  2. Create workflow file .github/workflows/claude.yml:
name: Claude Code

on:
  issue_comment:
    types: [created]
  pull_request_review_comment:
    types: [created]
  issues:
    types: [opened, assigned]
  pull_request_review:
    types: [submitted]

jobs:
  claude:
    if: |
      (github.event_name == 'issue_comment' && contains(github.event.comment.body, '@claude')) ||
      (github.event_name == 'pull_request_review_comment' && contains(github.event.comment.body, '@claude')) ||
      (github.event_name == 'pull_request_review' && contains(github.event.review.body, '@claude')) ||
      (github.event_name == 'issues' && (contains(github.event.issue.body, '@claude') || contains(github.event.issue.title, '@claude')))
    runs-on: ubuntu-latest
    permissions:
      contents: write
      pull-requests: write
      issues: write
      id-token: write
      actions: read
    steps:
      - name: Checkout repository
        uses: actions/checkout@v6
        with:
          fetch-depth: 1

      - name: Run Claude Code
        id: claude
        uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}

Usage

Comment @claude review this PR on any PR → Claude responds with analysis

Verification
  • Claude GitHub App installed on organization
  • ANTHROPIC_API_KEY added as repo secret
  • .github/workflows/claude.yml committed
  • Test: comment "@claude review" on PR → Claude responds

Claude Code Ecosystem

Claude Code's power comes from extensions: MCP servers (tools), plugins (behaviors), and skills (knowledge). This section covers everything you need to set up.

Extension Layers
  • MCP Servers — Background tools giving Claude access to external data/APIs
  • Plugins — Curated behavior packages from marketplaces
  • Skills — Markdown-based instructions teaching workflows
  • Subagents — Parallel worker agents for tasks

MCP Servers (Model Context Protocol)

MCP servers run as background processes giving Claude access to external tools.

Context7 — Live Documentation Lookup

What: Fetches up-to-date, version-specific docs for any library. When Claude needs React, Django, or Stripe docs, Context7 pulls real docs instead of relying on training data.

Why: Claude's training data has a cutoff. Context7 ensures current documentation, not outdated syntax.

API Key: Get free key at context7.com/dashboard

  • Keys format: ctx7sk_*
  • Free tier has rate limits; API key removes them

Setup:

claude mcp add context7 -- npx -y @upstash/context7-mcp@latest

With API key (recommended):

claude mcp add context7 -- npx -y @upstash/context7-mcp@latest --api-key ctx7sk_YOUR_KEY

Usage: Add use context7 to your prompt:

Build a Stripe checkout page. use context7

Hyperbrowser — Cloud Browser Automation

What: Cloud-hosted browser for web scraping, crawling, data extraction, and browser agent tasks. Unlike Playwright (local), Hyperbrowser runs browsers in the cloud.

Why: Use for browser automation without installing Chromium locally. Good for scraping and extracting structured data at scale.

API Key: Get key at hyperbrowser.ai

  • Free tier available
  • Key format: hb_*

Setup:

claude mcp add hyperbrowser -- npx -y hyperbrowser-mcp --env HYPERBROWSER_API_KEY=hb_YOUR_KEY

Available tools:

  • scrape_webpage — Extract formatted content
  • crawl_webpages — Navigate multiple pages
  • extract_structured_data — HTML to JSON
  • search_with_bing — Web search
  • browser_use_agent — Full automation

Agent Browser — Local Browser Automation

What: Local alternative to Hyperbrowser. Runs headless Chromium on your machine for testing, form filling, screenshots.

Setup:

npm install -g agent-browser
agent-browser install           # Downloads Chromium
npx playwright install          # Alternative

No API key needed — runs locally.

Subagents & Agent Teams

Subagents (Built-in)

Subagents are focused worker agents Claude spawns within a session. They execute tasks and report results back.

When to use: Quick, focused tasks where only the result matters.

Example prompt:

Use 3 parallel task agents: one to fix type errors,
one to fix import errors, one to fix null checks.
Report back when each completes.

Agent Teams (Experimental)

Agent Teams are multiple Claude Code instances that work together, communicate, and share a task list.

When to use: Complex work requiring discussion and collaboration.

Enable in settings.json:

{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}

Start a team:

Create an agent team to review PR #142. Spawn three reviewers:
- One focused on security implications
- One checking performance impact
- One validating test coverage
Have them each review and report findings.

Key controls:

  • Shift+Up/Down — Select teammates
  • Shift+Tab — Toggle delegate mode (lead coordinates only)
  • Ctrl+T — Toggle shared task list
Feature Subagents Agent Teams
Context Own window, results return Own window, fully independent
Communication Report back to main only Teammates message each other
Coordination Main agent manages all Shared task list, self-coordination
Token cost Lower Higher
Best for Focused tasks Complex collaborative work

  1. Copy the entire transcript
  2. Open Gemini (Google's AI)

Read this meeting transcript and extract the technical requirements

- What needs to be built/fixed

Settings Split (Environments)

Split settings into multiple files for different environments:

config/settings/
├── __init__.py
├── base.py        # Common settings
├── development.py # Local development
├── test.py        # Testing
└── production.py  # Production

Usage:

# Development
python manage.py runserver --settings=config.settings.development

# Testing
pytest --ds=config.settings.test

# Production
export DJANGO_SETTINGS_MODULE=config.settings.production
gunicorn config.wsgi:application

Security Hardening

Essential security settings for production:

# production.py
SECRET_KEY = os.environ['SECRET_KEY']  # Never hardcode!
DEBUG = False
ALLOWED_HOSTS = ['yourdomain.com']

# HTTPS/SSL
SECURE_SSL_REDIRECT = True
SESSION_COOKIE_SECURE = True
CSRF_COOKIE_SECURE = True
SECURE_HSTS_SECONDS = 31536000

# Security headers
SECURE_CONTENT_TYPE_NOSNIFF = True
SECURE_BROWSER_XSS_FILTER = True
X_FRAME_OPTIONS = 'DENY'

# CORS (if using separate frontend)
CORS_ALLOWED_ORIGINS = [
    "https://yourdomain.com",
]

# Database - use DATABASE_URL from environment
DATABASES = {
    'default': dj_database_url.config(
        default=os.environ.get('DATABASE_URL'),
        conn_max_age=600,
    )
}

OpenAPI TypeScript Codegen

Generate type-safe API client from Django's OpenAPI schema.

Install:

npm install openapi-typescript openapi-fetch --save-dev

Generate types:

# From Django backend OpenAPI endpoint
npx openapi-typescript http://localhost:8000/api/schema/ -o ./types/api.ts

# From local schema file
npx openapi-typescript ./schema.yaml -o ./types/api.ts

Usage:

import createClient from 'openapi-fetch';
import type { paths } from './types/api';

const client = createClient({
  baseUrl: 'http://localhost:8000/api'
});

// Fully typed!
const { data, error } = await client.GET('/users/{id}/', {
  params: { path: { id: 123 } }
});

// data is typed as User
// error is typed as ErrorResponse

ESLint & Prettier Setup

eslint.config.mjs:

import { dirname } from "path";
import { fileURLToPath } from "url";
import { FlatCompat } from "@eslint/eslintrc";

const __filename = fileURLToPath(import.meta.url);
const __dirname = dirname(__filename);

const compat = new FlatCompat({
  baseDirectory: __dirname,
});

const eslintConfig = [
  ...compat.extends("next/core-web-vitals", "next/typescript"),
  {
    rules: {
      "@typescript-eslint/no-unused-vars": "warn",
      "@typescript-eslint/no-explicit-any": "warn",
    }
  }
];

export default eslintConfig;

.prettierrc:

{
  "semi": true,
  "trailingComma": "es5",
  "singleQuote": false,
  "printWidth": 80,
  "tabWidth": 2
}

Run checks:

# Lint
npm run lint

# Format check
npx prettier --check .

# Format fix
npx prettier --write .

# Type check
npx tsc --noEmit

Vercel Deployment

Next.js deploys seamlessly to Vercel with zero configuration.

Environment Variables

Add to Vercel Dashboard → Project → Settings → Environment Variables:

NEXT_PUBLIC_API_URL=https://api.yourapp.com
SENTRY_DSN=https://...
NEXT_PUBLIC_SENTRY_DSN=https://...
DATABASE_URL=postgres://...

Note: Variables prefixed with NEXT_PUBLIC_ are exposed to the browser.

Build Configuration

vercel.json:

{
  "buildCommand": "npm run build",
  "outputDirectory": ".next",
  "framework": "nextjs",
  "installCommand": "npm ci"
}

Deployment

# Install Vercel CLI
npm install -g vercel

# Login
vercel login

# Deploy
vercel

# Deploy to production
vercel --prod
