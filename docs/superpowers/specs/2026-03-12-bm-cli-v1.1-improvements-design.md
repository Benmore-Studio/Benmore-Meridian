# bm CLI v1.1 Improvements — Design Spec

**Date:** 2026-03-12
**Status:** Approved
**Scope:** One PR — `bm skill remove`, universal `--dry-run`, and SKILL.md validation

---

## What We're Building

Three complementary improvements to the bm CLI that collectively eliminate the most common foot-guns in day-to-day skill management:

1. **`bm skill remove <name>`** — safe uninstall of repo-managed skills
2. **`--dry-run` flag** on `bm install`, `bm update`, `bm skill remove`, and `bm registry sync`
3. **SKILL.md frontmatter validation** — catches authoring errors at install time, not invocation time

---

## Why This Approach

**Approach B (DryRunContext object)** was chosen over a threaded `dry_run: bool` parameter. The context object:
- Collects all planned operations in one place for consistent output rendering
- Is easy to unit-test (inspect `ctx.ops` without parsing stdout)
- Pays forward — any new mutating command gets dry-run for free by accepting `ctx`

---

## Architecture

### New Module: `bm/bm/dryrun.py`

```python
@dataclass
class DryRunOp:
    verb: str        # "symlink" | "copy" | "remove" | "registry_add" | "registry_remove"
    target: str      # human-readable description of what changes
    source: str = "" # optional source path

@dataclass
class DryRunContext:
    dry_run: bool = False
    ops: list[DryRunOp] = field(default_factory=list)

    def record(self, verb: str, target: str, source: str = "") -> None:
        """Record an operation. No-op when dry_run=False."""
        if self.dry_run:
            self.ops.append(DryRunOp(verb, target, source))

    def render(self) -> None:
        """Print a Rich table of planned operations. Called at end of dry-run commands."""
        ...
```

**Signature changes required:**
- `install_skill(skill, claude_dir, ctx)` — records symlink/copy, skips writes when `ctx.dry_run`
- `Registry.batch_add(entries, ctx)` — records registry_add ops, skips JSON write when dry
- `Registry.remove(name, ctx)` — records registry_remove, skips JSON write when dry
- `Registry.sync(ctx)` — records all add/update/remove ops, skips writes when dry

All commands pass a `DryRunContext(dry_run=True)` when the flag is set. At the end of each command, if `ctx.dry_run`, call `ctx.render()`.

### New Command: `bm skill remove`

**Command signature:** `bm skill remove <name> [--dry-run]`

**Behavior:**
1. Look up `<name>` in the registry. If not found → `typer.Exit(1)` with error message.
2. If `install_method == InstallMethod.EXTERNAL` → refuse: *"This skill was not installed by bm. Remove it manually from `~/.claude/skills/<name>`."*
3. Record or execute: remove `~/.claude/skills/<name>` (symlink or directory). If missing, warn and continue.
4. Record or execute: `registry.remove(name, ctx)`.
5. Print success: `✅ Removed skill '<name>'`

**No `--force` flag** — EXTERNAL skills are the only guard; there's no dependency tracking in scope.

**New function in `installer.py`:**
```python
def remove_skill(name: str, claude_dir: Path, reg: Registry, ctx: DryRunContext) -> None:
    ...
```

**CLI hook in `cli.py`:** Under the existing `skill` app:
```python
@skill_app.command("remove")
def skill_remove(name: str, dry_run: bool = typer.Option(False, "--dry-run")) -> None:
    ...
```

```python

    """
    Returns a list of error strings. Empty list = valid.
    Errors block installation (skill gets FAILED result).
    Warnings are printed separately but don't block.
    """
```

**Required fields** (errors → FAILED):
| Field | Check |
|-------|-------|
| `name` | Present and non-empty in frontmatter |
| `name` match | Frontmatter `name` matches directory name |
| `description` | Present and non-empty |

**Optional fields** (missing → warning to stderr, install continues):
| Field | Expected format |
|-------|----------------|
| `version` | Semver string (e.g. `1.0.0`) |
| `author` | Non-empty string |
| `tags` | Comma-separated list |

**Integration:** Called in `discover_skills()` after each `SkillEntry` is constructed. Validation always runs (even in dry-run) — errors should surface before any writes.

**Frontmatter parsing:** Use simple regex extraction of the YAML block between `---` delimiters at the top of SKILL.md. No new dependencies needed (PyYAML is not required; key: value parsing is sufficient for these simple fields).

## Error Handling

| Scenario | Behavior |
|----------|----------|
| `bm skill remove` on unknown skill | Error + exit 1 |
| `bm skill remove` on EXTERNAL skill | Error + exit 1, no `--force` |
| `bm skill remove` on already-missing symlink | Warning + continue (still removes registry entry) |
| SKILL.md missing required frontmatter | `FAILED` result, NOT added to registry, error to stderr |
| SKILL.md missing optional frontmatter | Warning to stderr, install continues |
| Dry-run with valid ops | Print ops table, exit 0, no writes |

## Key Decisions

- **DryRunContext over threaded bool** — single place for op collection, renderable, testable
- **Validation errors block, warnings don't** — consistent with v1.0.1's FAILED result behavior
- **No `--force` on remove** — YAGNI; the only guard is EXTERNAL source, which is a hard stop
- **Simple frontmatter parsing** — regex over `---` block; no PyYAML dependency added
