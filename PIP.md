## What We Expect From You

### 1. Code Quality & Engineering Standards
- Write clean, readable code that follows established patterns
- Handle errors properly and account for edge cases
- Use consistent naming conventions, file structure, and architecture
- Optimize database queries. Don't ship what you don't understand.

### 2. Dev Checklist Compliance
- Follow every item in the dev checklist. No shortcuts.
- Your PRs should reflect checklist adherence before submission
- Follow proper branching strategy and commit hygiene

### 3. AI Tool Usage (Claude Code)
We use AI-assisted development tools to move faster. That said, these tools are an **accelerator**, not a replacement for your engineering skills. Here's how we expect you to use them:

- Every piece of AI-generated code must be reviewed, understood, and validated before you commit it
- If you cannot explain what your code does and why, it doesn't get merged
- Tests must accompany AI-generated code. If the AI didn't write tests, you write them.
- Copy-pasting AI output without reading it is not engineering. Don't do it.

You were hired because you're a software engineer. We expect you to think like one, even when AI is doing some of the heavy lifting.

### 4. Testing & QA
- Write unit tests that are meaningful, not just for coverage numbers
- Test integration points
- Perform manual QA before marking tasks as complete
- Verify in staging. "It works on my machine" is not acceptable here.

### 5. Documentation & Communication
- Write self-documenting code with clear comments where logic is complex
- PR descriptions should be thorough. What changed, why, and how to test.
- Communicate blockers and issues early, not at deadline

### 6. Ownership & Accountability
- You own your deliverables end to end
- Bugs in your code are your responsibility to fix promptly
- Meet your deadlines or communicate ahead of time with clear reasoning

## Monthly Performance Reviews

Every developer at Benmore undergoes a monthly performance review. This is not optional and it applies to all projects and all developers regardless of tenure. Here's how it works:

- **Frequency:** Monthly
- **Scope:** All active projects and repositories you contribute to
- **Reviewers:** Engineering leadership will audit your repos, PRs, commit history, and deployed code
- **Format:** You'll receive a written scorecard against the criteria listed above
- **Duration:** Indefinitely. This is a permanent part of how we operate.

### Scoring

| Rating | What It Means |
|--------|---------------|
| **Exceeds Standard** | Consistently ships quality code, follows all processes, strong ownership. You're the benchmark. |
| **Meets Standard** | Solid work, follows the checklist, minor areas for improvement. Keep it up. |
| **Below Standard** | Noticeable gaps in quality, checklist compliance, or AI tool misuse. You'll receive specific action items with a 30-day window to improve. |
| **Unacceptable** | Repeated failure to meet standards, vibe coding with no review, disregard for processes. This leads to termination. |

Two consecutive months of **Below Standard** or any month rated **Unacceptable** will result in termination.

This isn't meant to scare you. The bar is clear, the resources are available, and plenty of developers on this team consistently meet and exceed the standard. If you follow the checklist, take ownership of your work, and use AI tools responsibly, you'll be fine.

## Your First Steps

Before you start your first task:

1. Read the dev checklist cover to cover
2. Set up your development environment following the documented process
3. Familiarize yourself with the repos you'll be working on
4. Review recent PRs from senior developers to understand the standard
5. Ask questions. Seriously. It's better to ask now than to fix problems later.
