Claude Code Agent Teams Guide

Practical Reference for Multi-Agent Orchestration
Key Takeaways
  • Agent Teams = multiple Claude Code instances with a shared task list and inter-agent messaging
  • "Swarm mode" is the community name; Anthropic calls them Agent Teams
  • Enable via CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1 in the settings.json env block
  • Shipped alongside Opus 4.6 on February 5, 2026
Agent Teams vs Subagents
Criteria Subagents Agent Teams
Communication Report back to main only Teammates message each other

Best for Focused tasks, result-only Complex work needing discussion

Best Use Cases

Research and Review

Multiple teammates investigating different aspects simultaneously, synthesizing findings into a unified report.

New Modules / Features

Each teammate owns a separate piece of the implementation without merge conflicts.

Competing Hypothesis Debugging

Test different theories about a bug in parallel, converge on the root cause faster.

Cross-Layer Coordination

Frontend, backend, and tests each owned by a different teammate working concurrently.

Parallel Code Review

Security, performance, and test coverage audits running simultaneously across the same codebase.

Display Modes
Default

In-Process Mode

All teammates run inside the main terminal session. Use Shift+Up/Down to navigate between them.

Works in any terminal emulator. Best when you just want results without extra panes.

Optional

Split-Pane Mode

Each teammate gets its own pane. Requires tmux or iTerm2 with the it2 CLI installed.

Launch with claude --teammate-mode tmux. Best for monitoring live progress.

Architecture
Team Lead
Your main Claude Code session that spawns and coordinates the team
Teammates
Separate Claude Code instances running in parallel
Task List
Shared board stored at ~/.claude/tasks/
Mailbox
Direct inter-agent messaging for coordination
Key Controls
  • Shift+Up/Down Navigate between teammates
  • Shift+Tab Toggle delegate mode (coordination-only for lead)
  • Ctrl+T Toggle shared task list view
  • Enter View selected teammate session
  • Escape Interrupt the current teammate
Cost Awareness
  • Every teammate has its own full context window
  • Every inter-agent message costs tokens
  • Start with 2-teammate teams on research tasks before scaling up
  • Not worth it for simple sequential tasks one agent could handle
Session Lifecycle
1
Create team and spawn teammates with clear role definitions
2
Teammates claim tasks from the shared list and work in parallel
3
Inter-agent messaging for coordination and dependency resolution
4
Lead synthesizes results from all teammates into final output
5
Shutdown teammates via the lead when work is complete
6
Panes stay open for review (one team per session)
Known Limitations
  • Teammate resumption is limited — /resume will not restore in-process teammates
  • Task status can lag — teammates sometimes fail to mark tasks as completed
  • No nested teams — teammates cannot spawn their own teams
  • Lead is fixed — you cannot promote a teammate to lead mid-session
  • Permissions set at spawn — all teammates inherit your permission mode
Subagent Memory

Memory Scopes

user ~/.claude/agent-memory/ Cross-project learnings (recommended default)
project .claude/agent-memory/ Project-specific, shareable via git
local .claude/agent-memory-local/ Project-specific, private to your machine

Memory vs CLAUDE.md

CLAUDE.md

Static instructions you write and control. Loaded at session start and shared with all teammates.

Agent Memory

Dynamic knowledge the agent discovers over time. Compounds across conversations — reviewers learn your patterns.
